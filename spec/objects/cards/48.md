# 48 — 计算

主类11；genera随结果量纲变化，常见51（无单位）、48（长度）、49（角度）、50（面积），不能按约束48写死类型。49,419个对象，是本批优先实现的数值来源。父表2002是表达式引用的对象槽，按原生顺序读取；父可以是度量、参数、另一个计算或函数。

## 存储与引用

表达式在2311里保存为**u16中缀token**，不是UTF-8字符串，也不是HTML的RPN。共同显示前缀32字节；+36 u32恒等于载荷长−32；+40 u32为48；+44 u16是token个数N；+46 u16在全语料恒为4（具体名称未知）；+48..91保留；+92开始N个u16，载荷长92+2N。49,419个本类载荷全部满足。`+48..91`中有残留/过程态数据，不能清零或当数值常量使用。详见格式规格§8.11。

| token | 含义 |
|---|---|
| 0..9 | 数字字符0..9；相邻数字组成一个数 |
| 10 | 小数点 |
| 11 / 12 | 左括号 / 右括号 |
| 13 / 14 | π / e 常数 |
| 0x1000..0x1004 | 加、减、乘、除、幂；减号在操作数位置表示一元负号 |
| 0x2000..0x200C | 依次sin,cos,tan,asin,acos,atan,abs,sqrt,ln,log,sgn,round,trunc；函数token自带左括号，末尾由12关闭 |
| 0x6000+i | 当前对象2002父表的第i槽（0起）；不是全页对象编号 |
| 0x7000+i | 调用第i父函数，后跟实参及右括号12；本批不要求实现函数对象，明确报未支持 |
| 0x0100 / 0x0101 | 显式弧度 / 度单位后缀 |
| 0x0201 | 显式厘米后缀 |

0x0102（方向度）、0x0200（像素）、0x0202（英寸）属于单位token族的静态候选，未在本批独立核对，读入时保留；不得凭猜测吞掉其它token（方程成分等后续类型仍存在）。

例：`[0x6000,0x1003,2]`是`parent[0]/2`；`[3,10,5,0x1002,0x6000]`是`3.5*parent[0]`；`[0x200C,0x6000,12]`是`trunc(parent[0])`。HTML会将它们分别输出为`A 2 /`、`3.5 A *`、`A @trnc`。换成父槽1或交换除法左右不能得到同一表达式，绑定时必须比较有序父表及非交换运算结构。

## 数学语义与量纲

通常优先级为括号/函数、幂、乘除、加减；一元负号与幂结合、连续幂的结合方向仅有静态数学解释，本批未用原版边界输入实验确认，不得将研究解析器的一种实现当成最终证据。基础单层四则和显式括号已由HTML非交换表达式核对。

引用父值应取父的**未舍入显示单位值**（见下）。HTML 把显式 `360度`、`4厘米` 写成 6.28319、151.181（弧度、页面 px，约 6 位有效数字），这只是 HTML 导出的写法，不代表原生只存这些小数，也不是原生求值的单位。sgn 按正/零/负返回 1/0/−1；abs 为绝对值、sqrt 为算术平方根、ln/log 为自然/常用对数。round(x) 按手册相当于 floor(x+0.5)，trunc 向零截断。Java 导出 trunc 使用 floor，不能移植为原生规则。

### 求值模型（2026-10-24 定稿，取代本卡片早先“内部一律基准单位”的写法）

整条表达式在**页面显示单位**里求值，详见[度量验收契约](../../acceptance/m5-measures.md)“求值模型”一节：

1. 父槽 `0x6000+i` 的值 = 该父的未舍入读数，单位是该父量纲下的页面显示单位（长度 = 10041 指定单位，角度 = 10042 指定单位，面积 = 长度单位²，无量纲 = 纯数）。
2. 单位后缀 `0x0100`（弧度）、`0x0101`（度）、`0x0201`（厘米）只作用于紧挨着的数字字面量或 π/e，把它换算进当前页面单位：度页面上 `90°` 仍是 90，弧度页面上变成 π/2；厘米页面上 `24 cm` 仍是 24，英寸页面上是 24/2.54，像素页面上是 24·DPI/2.54。后缀出现在其它位置，或遇到 `0x0102`/`0x0200`/`0x0202`，报 `expression-unsupported:<token>`。
3. `sin cos tan` 把参数按页面角度单位解释（度页面即 `sin(x·π/180)`）；`asin acos atan` 的结果用页面角度单位给出。
4. **求值时不做量纲检查**：`90° − asin(x)`、`number − angle` 都合法，值照算（原版语料有 9 例这类写法给出正确读数）。
5. 结果的显示单位和 `internal.magnitude` 的换算由下一节的**结果量纲**决定。

证据：独立复算原版读数 420/422 一致，另 13 条差异全部由字体字形解释（见 [m5-batch1 验收](../../acceptance/m5-batch1.md) §8）。负号与幂的结合、连续幂的结合方向仍只有静态解释（本实现：幂右结合，且比一元负号紧，`-2^2 = -4`）。

### 结果量纲：表达式推得的量纲必须与对象头 genera 一致

对象头 genera 51/48/49/50 分别表示 number/length/angle/area。实现另外从表达式推一个量纲，**只用于和 genera 核对**，不参与求值：

| 构造 | 推得的量纲 |
|---|---|
| 数字字面量、π、e | number |
| 字面量 + `0x0100`/`0x0101` | angle |
| 字面量 + `0x0201` | length |
| 父槽 | 父的量纲 |
| `+` `-` | 两侧有一侧是 number 时取另一侧；否则取左侧 |
| `*` | 一侧 number 时取另一侧；length×length = area；其余取左侧 |
| `/` | 分母 number 时取分子；同量纲 = number；area÷length = length；其余取左侧 |
| `^` | 底数 number → number；底数 length 且指数 number → area；其余取底数 |
| `sin cos tan ln log sgn` | number |
| `asin acos atan` | angle |
| `abs round trunc` | 同操作数 |
| `sqrt` | area → length，其余 → number |

- 两者一致（语料绝大多数）：按这个量纲选 `displayUnitText`、换算 `internal.magnitude`。
- **两者不一致**：报 `status:"unsupported", reason:"dimension-mismatch-unverified"`，`internal` 诊断可以另外写进 debug 输出，但**不输出 `measurement`**。原版在这种情况下显示哪个单位还没有核实（如 `P0*P1` 在 genera=51 时显示空单位还是 `厘米²`，见 questions.md Q9.1）；全语料约 190 个这类对象，r3 集合里没有一条读数断言，所以报未支持不会丢掉已验证的覆盖。
- genera 不在 48–51 中：同样报未支持。

上述规则之外，`0x7000+i` 函数调用、任何未列 token，一律**显式未支持**，不得猜一个数。手册说 `(4平方厘米)^0.5` 得到无单位 2，而 `sqrt` 得到 2 厘米；本批不区分这两者以外的幂量纲。

**父槽可以引用什么**：数值自由对象（[0.md](0.md) 的约束0/主类11，值取它自己的 2311；genera 57 的函数定义除外）、本批度量 36–47、其它计算 48。父槽指向没有数值的对象（如几何点、线段）时报未支持，不做隐式换算。

单位算术不能简单套通用物理量系统：手册说明sqrt(4平方厘米)得到2厘米，但(4平方厘米)^0.5得到无单位2。不同量纲组合、幂和单位消去的完整规则尚未动态验证，本批先实现已证实的量纲相容算式；不支持的单位组合必须显式保留未支持。不要把屏幕数值直接代入长度/角度变换。

手册说明1/0为∞、−1/0为−∞、0/0和sqrt(−1)未定义、0^0为1。因此数学非有限值、几何不存在、表达式语法/类型未支持应分开记录；有∞的表达式不是读档失败，且下游几何仍需检查参数是否可用。本批十进制期望不覆盖∞和π分数。

## 验收与证据

见[度量验收契约](../../acceptance/m5-measures.md)。词法结构来自原版存档与已有HTML RPN；语义来自原版手册。至少268个对象通过独立父图和中缀/RPN结构核对，但不是13个函数全部动态原版求值实验。`tools/m5_measures.py`只为结构核对解析表达式，**绝不用表达式求值生成期望**。真实数值期望由EMF显示文字提供。未知函数调用祖先可令此对象阻塞，但已有错误数值不得隐藏为祖先未实现。
