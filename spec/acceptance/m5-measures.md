# 度量与计算：本批规格与验收边界

2026-10-24，离线读取原版存档及既有 `oracle/full` EMF/HTML，未启动原版。实现入口为对象卡片 36–48、65、66、86、94 与格式规格 §8.11。

## 值、单位、精度

数值父对象传递数值，不能从它的标签、屏幕文字或已经舍入的字符串反求内部值。长度内部建议以页面 px 表示，角以弧度表示；距离单位换算 `px/cm = pageDpi/2.54`、`px/in = pageDpi`，本批所有页 DPI 为 96。面积相应使用平方换算。无单位的比值、点值和坐标值不随距离显示单位变化。单位不是仅有一条全局显示字符串：计算的显式单位必须参与求值。

页面 `10041` 是距离单位码（0 px、1 cm、2 in）；`10042` 是角度单位码（0 弧度、1 普通度、2 方向度）。角度码 1 的三点角取 [0,π]，码 0/2 取 [-π,π] 且逆时针为正。语料中 2,455 页的 `(10041,10042)` 分布为 `(1,1):1637,(1,0):592,(1,2):207,(0,0):17,(2,1):2`。厘米与角度三种模式有既有 EMF 对照；英寸/像素换算是静态规则加显式常数的结构证据，未新增 UI 单位切换实验。**10021 的业务含义仍未知，不能把它当单位码。**

2307/2311 的共同前缀见格式规格。当前语料 `<0>` 模板的 `+28 u16` 是对象小数位数，0..5；已检查的原版十进制读数与这个字段一一相同，含 0/1/2/3/4/5 六种精度；正式数量以严格生成的证据报告为准。`10040` 是页面三类默认精度槽，具体槽到长度/角度/其它的映射尚未独立验证；已有对象应使用自己的字段，不用页面默认精度覆盖。原版内部值不会因显示精度变低而被截断。

一般显示舍入的负半值边界尚未实验，不能把计算函数 `round()` 的规则直接推广为所有文字的舍入规则。手册明确计算函数 `round(-1.5)=-1`、`trunc(-1.3)=-1`；Java 导出运行库的 trunc 使用 floor，与原生手册不同，只能用于核对表达式结构，不能移植该函数语义。

## 原版期望值与实际输出协议

`tools/emf_match.py` 生成的 `kind="measure"` 断言具有 `measurement={displayValue,displayNumber,displayUnitText,digits,roundingTolerance}`。数字与单位来自原版 GDI TextOut；`displayValue` 是**显示单位中的有限精度读数**，不是精确内部值，也不是页面 px。匹配只使用保存的文字位置、原版图元的独立页面平移、文字颜色、唯一 `=` 后的数字，不根据预测数值筛选。

实际 core JSON 同样使用 `kind="measure",exists=true,measurement={displayValue,displayUnitText}`；若还提供 `displayNumber` 则要求与原版字符完全相同。单位必须相同，数值容差为最后一位的半个单位（另加极小浮点裕量）。精确单位字形也保留，例如 Symbol 字体的 `U+F0B0` 与普通 `°`。**缺少displayNumber时只验证数值显示区间与单位，不验证显示字符串、舍入规则、digits或格式。**提供displayNumber时才逐字验证数字部分；本批case和报告继续将样式/标签/完整显示格式标为未验收。实现仍应单独保存未舍入的内部值。

## 数值对象的输出协议（本批实现契约）

数值对象（度量 36–47、计算 48、参数 0/主类11）在 dump 里输出：

```json
{"objectIndex": 12, "constraintId": 36, "exists": true, "status": "ok", "kind": "measure",
 "measurement": {"displayValue": 2.51, "displayNumber": "2.51", "displayUnitText": "厘米",
                 "internal": {"dimension": "length", "magnitude": 94.87}}}
```

- `internal.magnitude` 是**未舍入的内部值**，基准单位固定：`length` 页面 px、`angle` 弧度、`area` 页面 px²、`number` 无量纲。它是本批新增的调试字段，比较器不读；没有它就无法判断舍入边界，也无法与变换参数对齐。
- `internal.displayRaw` 是同一值的**显示单位未舍入读数**（`magnitude` 除以单位换算系数）。验收用它判断一条断言是否落在半值边界（`raw·10^digits` 的小数部分与 0.5 相差 ≤1e-9）。
- `displayValue` 是**显示单位里的读数**：实现按 `digits` 舍入后再换算回来，必须与 `displayNumber` 自洽（`parse(displayNumber) === displayValue`，`digits=0` 时 `displayNumber` 无小数点）。
- `displayNumber` **可以省略**，但省略时比较器只验区间；本批要求：只有当一个值落在舍入边界（十进制 `digits` 位上恰为 `x.5` 的 ±1e-6 个末位单位以内）时才省略，并在报告里单独计数。这类值不能算作“舍入规则已验证”。
- 单位文字由**页面偏好**、**量纲**和**对象字体**共同决定，逐字一致（表见下节）。面积的上标布局本批仍不验收。
- `digits` 取对象自己 2307/2311 共同前缀 `+28`，不用页面 10040。DPI 取页面 9008（本语料 96），不用 EMF 导出 DPI。

### 单位文字表（逐字）

| 量纲 | 页面偏好 | 对象字体 | `displayUnitText` | 语料条数 |
|---|---|---|---|---|
| `length` | `10041=1` | 任意 | `厘米` | 68 |
| `length` | `10041=0` | 任意 | `像素`（字形未经原版核对） | 0 |
| `length` | `10041=2` | 任意 | `英寸`（字形未经原版核对） | 0 |
| `angle` | `10042=0` | 任意 | `弧度` | 4 |
| `angle` | `10042=1` 或 `2` | Arial / Times New Roman 等正文 | `°`（U+00B0） | 42 |
| `angle` | `10042=1` 或 `2` | `Symbol` | `U+F0B0` | 1+（此前独立核对 6/6） |
| `number` | 任意 | 任意 | 空串 | 1,300+ |
| `area` | — | — | 本批不验收 | 0 |

关键点：**`10042` 的 1 与 2 都是度数**，区别只在 41 的符号约定（1 取绝对值，0/2 保留有向符号）；字形由对象样式指向的字体决定，Symbol 字体下是私用区 `U+F0B0`，其余字体是 `°`。因此实现必须解析 `2008 → 1203[fontIndex] → 1201` 才能拿到字形，不能只看 `10042`。10041=0/2 的字形字符串来自任务书给定的码位含义，语料无样本，属低置信项，已在 `questions.md` 登记。


**非有限值与四类“没算出来”必须分开报告**（比较器只看 `status`/`reason`，报告按 reason 前缀分类）：

| 情形 | 输出 | 报告类 |
|---|---|---|
| 值算出来且有限 | 上表 | 通过 / 算错 |
| 值发散（如 `1/0`） | `status:"unsupported",exists:null,reason:"value-infinite"` | 未支持（不是算错） |
| 数学无定义（`0/0`、`sqrt(−1)`、零边夹角、零分母比） | `...reason:"value-undefined"` | 未支持 |
| 几何父不存在 | `status:"not-existing"`,reason 说明 | 不存在（不计通过） |
| 表达式语法/单位组合/函数调用超出契约 | `...reason:"expression-unsupported:<token>"` 等 | 未支持 |
| 父对象本身未实现 | `status:"unsupported",exists:null,reason:"parent:N:unsupported"` | `blocked_by_unimplemented_ancestor` |

**绝不能**为了凑通过而输出一个错误的有限值；也不能把 `∞` 写成很大的有限数。有 `∞` 的表达式不是读档失败，读数断言本批不覆盖它们。

**量纲与 genera 交叉核对**：48 的对象头 genera 应等于 51/48/49/50 之一（number/length/angle/area）。实现应在 debug 输出里带上自己算出的量纲与这个字段，验收时统计不一致数；不一致不得靠改 genera 掩盖。

例：原版显示 `2.51厘米`，期望 `displayValue=2.51`、`displayNumber="2.51"`、`displayUnitText="厘米"`、`digits=2`；数值 2.512 可以进入此显示区间，2.52 不可以。同一数字的英寸值不能通过厘米断言。该区间不证明半值时原版采用何种舍入。

重复文字位置、重复图元归属、文字邻接歧义、非十进制/π 分数、面积单位的上标布局、没有独立页面对齐的文件都显式列为 coverage gap；不能伪造 0 或用自算值补齐。隐藏对象没有可见文字，不算已验证。坐标度量可有真实读数期望，但坐标系祖先尚未实现时应报告阻塞。

## 求值模型：数值在页面显示单位里，量纲只决定后缀

原版不是"内部一律基准单位、显示时换算"，而是**整个表达式都在页面显示单位里算**。证据：`90 deg/(P0+1)` 在厘米/度页面上得到 `45.00°`；`90 deg - asin(x)` 这类"数字减角度"的写法在原版里合法并给出正确读数（9 例）；把三角函数按页面角度单位换算后，独立复算与原版读数从 409 条升到 420 条一致。因此：

1. **量值模型**：一个数值对象的值就是一个 double，单位是该对象量纲下的**页面显示单位**（长度=10041 指定单位、角度=10042 指定单位、面积=长度单位²、无量纲=纯数）。不引入运行时量纲检查；`number - angle` 不报错。
2. **量纲只用于**：选 `displayUnitText`、选三角函数的角度换算、输出 `internal.dimension`、与对象头 genera 交叉核对（诊断，不覆盖值）。
3. **三角函数**：`sin/cos/tan` 的参数按页面角度单位解释（度页面即 `sin(x*π/180)`）；`asin/acos/atan` 的结果按页面角度单位给出。这与"值就在显示单位里"是同一件事，不是额外规则。
4. **常量与单位后缀 token**：`0x0100`=弧度、`0x0101`=度、`0x0201`=厘米。后缀作用于它前面的数值字面量，把该字面量**换算进当前页面单位**：`90` + `0x0101` 在度页面仍是 90，在弧度页面变成 `π/2`；`24` + `0x0201` 在厘米页面仍是 24，在英寸页面变成 `24/2.54`。`0x0102`/`0x0200`/`0x0202` 未核证，遇到即 `expression-unsupported:<token>`。
5. **`internal.magnitude`** 仍然按上节的基准单位输出（由显示单位值反算），这样下游不必知道页面偏好。
6. 页面偏好或 DPI 缺失、`9008` 非 96 且需要 DPI 的换算（英寸/厘米）、面积量纲，都按"值算不出来"处理，不要假设 96。

## 模块边界（本批分解，避免两人改同一文件）

| 归属 | 文件 | 内容 |
|---|---|---|
| W1 | 新建 `src/numeric/units.ts` | 页面偏好读取（10041/10042/9008）、单位换算表、单位后缀 token 表、字体字形解析（2008→1203→1201） |
| W1 | 新建 `src/numeric/expression.ts` | 2311 token 解码 → 中缀求值（13 函数、`0x6000+i` 父槽、`0x7000+i`/未知 token 显式未支持、`0x000F` 不得当数字） |
| W1 | 新建 `src/measure.ts` | 36/37/39/40/41/43/44/46/47/48 与数值自由对象（约束 0/主类 11）的求值、格式化、`measurement` 输出 |
| W1 | 改 `src/geometry.ts` | 只加 `kind:"measure"` 一类 outcome 与派发，不放变换/弧逻辑 |
| W2 | 改 `src/geometry.ts`、`src/arc.ts` | 18–20/23–26/29/31/33 解锁、75 动态颜色、79/80 离圆半径规则 |

`src/geometry.ts` 是本批唯一会被两人先后修改的文件：W1 先做并在提交点 C1 冻结，W2 从 C1 之后开始。两人不同时改。



`check_m2.py` 只在 actual 明确给出 `status="unsupported",exists=null,reason="parent:N:unsupported"` 且父链最终指向一个真实未实现对象时，将断言列为 `blocked_by_unimplemented_ancestor`。它不计入通过，也不计入算错；`--require-full` 不接受这种状态。对象自身未实现属于 `unimplemented_self`，仍计失败。缺失对象、失效父链、错误有限结果、已输出 NaN/非法几何始终失败；不得因为有未实现祖先而掩盖回归。75 若已有有效几何，不受未实现的颜色父影响。

## 证据等级与复查

- **结构验证**：1,431 存档；49,419 个约束48的2311全部符合规格的 token 区布局。`tools/m5_measures.py` 解码，未知 token 拒绝解释。
- **独立导出结构验证**：在对象数≤500的活动页中，至少268个48通过“自由点空间身份→父图→有序父槽→原生中缀与HTML RPN表达式树”唯一绑定。父引用不是HTML步骤号；交换除法/减法两侧会失配。函数数值域与舍入仅有手册证据，并非13函数全部动态实验。
- **数值核对**：`python tools/m5_specs_evidence.py oracle/m5-cases-r2 --out oracle/m5-evidence-r2.json` 比较原版显示数字与同一 EMF 已断言父几何所定义的度量。正式r2可核对的36/37/40/41/46/47分别为10/35/1/5/3/52条，共106条，0失配。另有3条有向负角，用原生已解A组父图重建坐标对照原版显示文字，反序均失败；这些父点不是独立EMF点量测，证据层级另列。47的负比仍只有静态语义，不冒充已验证。
- **静态语义**：本地使用手册的“度量”“点的值”“计算”“绘图”章节、对象目录的资源描述/父模板。65/66/86的坐标定义、94的复杂路径以及坐标系卡片仍有骨架范围限制。

几何期望继续保留原有原版 EMF 来源。本批新增的是数值显示期望，不能据此宣布 M5 已实现或全语料已支持。
