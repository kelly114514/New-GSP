# .gsp 文件格式规格 v1

版本：v1（2026-10-23）。

适用对象：几何画板 4.x / 5.x 存的 `.gsp` 文件（语料中的“布局 4”和“布局 5”）。读者是实现方，目标是 M1 的无损读写：任何语料文件读入再写出，字节完全一致。

本文配套两样东西：

- `record-kinds.json`：84 种记录 kind（外加语料中没有的 1004/1005）的机器可读表。
- `tools/check_gsp_grammar.py`：把本文的文法逐条写成检查，跑遍全部 1,431 个语料文件和 5 个基准样本，目前 0 违例。本文标“已验证”的结论，多数就是这个脚本在检查的。

## 1. 约定

### 1.1 证据等级

| 标记 | 含义 |
|---|---|
| 〔已验证〕 | 全语料检验（1,431 个文件）或原版 5.06 实验（基准样本、崩溃文件）得到 |
| 〔静态证据〕 | 来自对原程序的静态分析，没有做过原版实验 |
| 〔推测〕 | 由数据形态推断，没有第二个来源；不得当作事实实现 |
| 〔未知〕 | 不清楚；只能原样保留 |

### 1.2 术语

- **布局 5 / 布局 4**：900 头第一个 u16（§4）。语料中布局 5 有 1,410 个文件，布局 4 有 21 个（4.x 版本 Windows 构建存的）。两种布局的魔数都是 `GSP4`。
- **载荷**：记录头之后的字节，不含补齐。偏移默认指载荷内偏移，从 0 起，小端。
- **位置**：记录所处的容器，用于描述“哪种 kind 能出现在哪里”。

  | 位置名 | 含义 |
  |---|---|
  | `top` | 文件最外层（只有 900） |
  | `doc` | 900 之内 |
  | `compat` | 902 之内 |
  | `group` | 1006 之内 |
  | `page` / `tool` | 1000 / 1002 之内 |
  | `page>object` / `tool>object` | 页 / 工具区里的 2000 之内 |

- **残留字节**：原版写出时没有清零、带有内存旧值的字节。它们没有语义，但同一个文件里值各不相同，所以**必须逐字节保留**才能保证重存一致（§9）。

### 1.3 语料规模

“语料”指原版发行包里的全部 `.gsp`（`original/sketchpad5`，实现方的检出里不一定有）；文中提到的语料文件名都相对这个目录。“基准样本”指 `samples/baseline/samples` 里原版 5.06 生成并重开过的 5 个文件。

| 项 | 数量 |
|---|---:|
| 文件 | 1,431（布局 5：1,410；布局 4：21），共 59,994,160 字节 |
| 记录 | 1,907,414，kind 共 84 种 |
| 页（1000） | 2,455（布局 5：2,396；布局 4：59） |
| 自定义工具区（1002） | 1,108（布局 5：830；布局 4：278），分布在 134 个文件 |
| 对象（2000） | 400,744（28 字节头：360,923；16 字节头：39,821） |
| 嵌入图片（1300） | 370，分布在 204 个文件 |
| 兼容信封（902） | 4,973 |

## 2. 文件容器

```
file   := "GSP4" record*
record := u32 length | u32 kind | payload[length] | pad
pad    := 若 length 为奇数，则 1 个字节 00；否则没有
```

- 魔数 `47 53 50 34` 之后立即是第一条记录，没有别的文件头。〔已验证〕
- 全部整数小端。`length` 只算载荷，不含 8 字节记录头，也不含补齐字节。〔已验证〕
- 下一条记录的偏移 = 本记录偏移 + 8 + `length` + (`length` & 1)。即记录起点恒为偶数偏移。〔已验证〕
- 补齐字节：语料中共 457 个，全部是 `00`。〔已验证〕原版写入器逐字节写 0。〔静态证据〕读取器应把补齐字节视为不含信息；写出时写 `00`。
- 第一条记录必须是 900（28 字节载荷），最后一条必须是 901（空载荷），901 之后文件结束，没有尾随字节。〔已验证〕
- kind 是完整的 32 位值；语料里最大 10044。读取器不得因 kind 不认识而失败（§10）。
- 单条载荷最大 369,600 字节（一幅 PNG），长度字段不会超过文件剩余字节。
- 魔数不是 `GSP4` 的文件（原版代码里还认 `GSPk`、`GSPc` 和一种旧 Mac 格式）：语料里没有样本，本规格不覆盖。〔静态证据〕

## 5. 兼容信封 902/903

### 5.1 用途与位置

902/903 是原版的**前向兼容信封**〔静态证据〕：一个新版本程序写的内容，老版本读不了时，读到 902 头里的版本号就知道自己不认识，于是弹出信封里带的提示文字，然后整块跳过，把文档作为副本打开。每个页、每个工具区、以及“附加信息组”各有自己的信封。原版读取文档时，900 之内的每个成员**必须**是 902，否则报格式错误〔静态证据〕，所以**写新文件时必须写信封**。

位置规则见 §3.2。信封内除了内容容器和 903 之外没有别的记录。〔已验证〕

### 5.2 载荷结构〔已验证〕

```
u16 h[8]            ; 16 字节头
string[3]           ; 三个提示串，紧接头部，依次排列
string := u16 L | L 字节 | 00 | (若 2+L+1 为奇数) 1 个补齐字节
```

- 每个 string 占 (L+4)&~1 字节；整个载荷长度 = 16 + 三个 string 之和，恰好用完，其后没有别的字节。
- L 是 NUL 之前的字节数，等于实际长度；串内没有嵌入 NUL。
- 语料中的 4,973 个信封全部满足这个结构。
- **串末的补齐字节是残留，值不定**（语料中出现过 0 以外的上百种值），读取时跳过，原样保留，写新串时写 `00`。
- 空串合法：`00 00 00 pad`，占 4 字节。

头字段：

| 偏移 | u16 | 名称 | 取值 | 说明 |
|---:|---|---|---|---|
| 0 | h[0] | 内容类型 | 1=页，2=工具区，5=附加信息组 | 〔已验证〕与内部容器严格对应。原版代码还处理 0、3、4 和 ≥6，语料没有 |
| 2 | h[1] | 内容版本 | 页/工具 4，组 5 | 〔静态证据〕写入时的内容版本。读取方支持的版本低于它，但不低于 h[2] 时，内容照常读取，但要提示“可能丢失信息” |
| 4 | h[2] | 最低可读版本 | 页/工具 4，组 5 | 〔静态证据〕读取方支持的版本低于它，就读不了。语料中 h[1]=h[2] |
| 6 | h[3] | 未知类型时的提示等级 | 页：1 或 3；工具、组：3 | 〔静态证据〕见 §5.4 |
| 8 | h[4] | 版本过新时的提示等级 | 恒等于 h[3] | 〔已验证〕 |
| 10 | h[5] | 部分可读时的提示等级 | 页 2；工具 4；组 4 | 〔已验证〕取值；含义〔静态证据〕 |
| 12 | h[6] | 保留 | 恒 0 | |
| 14 | h[7] | 保留 | 恒 0 | |

h[3] 在页信封里的取值规则〔已验证〕：当文档**只有一页且没有任何工具区**时为 1，其余情况（多页或有工具）为 3；同一文件内所有页信封取值相同。提示等级 1 对应“无法打开”（错误），3 对应“作为副本打开”（警告）〔静态证据〕。

### 5.3 三个提示串

三个串依次是〔静态证据〕：

| 序号 | 何时显示 |
|---:|---|
| 0 | 内容类型读取方完全不认识 |
| 1 | 内容版本过新，读不了（h[2] 高于读取方支持的版本） |
| 2 | 内容能读，但可能丢失信息（h[1] 高于读取方支持的版本） |

语料中：页和工具信封的串 0 为空；组信封的串 0 与串 1 内容相同。

编码：与全文件的文本编码一致（§6）：布局 5 为 UTF-8，布局 4 为系统 ANSI（语料中为 GBK）。〔已验证〕串内可含 `0A`（LF）换行（原版 5.06 写出的组信封与页信封各有一个）。

读取方的内部缓冲只能放下 255 个 UTF-16 码元的串（三个缓冲各 0x200 字节），写入时应保证每个提示串转成 UTF-16 后不超过 255 个码元；更长的串会越界〔静态证据，推测其后果〕。语料中最长的串 145 字节。

### 5.4 原版读取判定〔静态证据〕

读取方对每种内容类型有一个“支持的版本”：类型 0→5、1→4、2→4、3→1、4→0（不支持）、5→5；≥6 不认识。令 V 为该支持版本，判定顺序如下：

1. 类型 ≥6，或 V=0：**未知类型**。提示等级取 h[3]，显示串 0，内容整块跳过（读到下一个 903 为止），结果为“警告：丢失信息”，文档作为副本打开。
2. V < h[2]：**版本过新**。提示等级取 h[4]；若 h[4]=1 或类型为 0，结果为“错误：无法打开”，否则为“警告”；显示串 1，内容整块跳过。
3. V < h[1]：**部分可读**。提示等级取 h[5]，显示串 2，内容照常读取。
4. 否则正常读取，不提示。
5. 提示等级 ≥6 的一律改为 1 并按错误处理；等级在 1..4 之间且对应串非空时才把提示串交给界面。

“整块跳过”的做法是逐条读记录直到遇到第一个 903，所以**信封内部不能再出现 903**，信封也不能嵌套。

结论（供以后加新功能时使用，〔静态证据〕，尚未做原版实验确认）：新功能的数据放进一个类型 ≥6 的新信封（h[1]、h[2] 填 6 以上，h[3] 填 3，串 0 写给用户的说明），老版本就会弹出串 0、跳过这一块并把文档作为副本打开，而文件其余部分正常读取。要让老版本拒绝某一页，也可以直接把该页信封的 h[1]、h[2] 提到 5 以上：老版本支持的页版本是 4，会按“版本过新”处理（单页无工具的文档 h[4]=1 时按错误拒绝打开；h[4]=3 时跳过该页并作为副本打开）。

### 5.5 写入规则与崩溃条件

提示串写错会让原版崩溃。〔已验证，原版 5.06 实验〕一个构造文件（本目录 `fixtures/crash-19byte-envelope.gsp`）把两个 902 都做成了 19 字节载荷（16 字节头 + 3 个 `00`），原版打开它时崩溃（事件日志记录了 0xC0000409 和 0xC0000005 两次异常）。原因〔静态证据〕：读取方找“下一个串”时，从当前串的起点跳过 2 字节长度，向后扫到 NUL，再把下一字节位置向上取偶；如果这个位置等于载荷末尾，认为“没有后继串”（报格式错误），**如果超出载荷末尾，则不检查就去读**，从越界位置取长度并做字符集转换，造成崩溃。

检查器 `tools/check_gsp_grammar.py` 会拒绝这个文件（用 `--root spec/format/fixtures` 可验证），实现方的写出器也应有对应的单元测试。

所以写信封时必须保证：

1. 恰好三个串，每个按 §5.2 的格式写；每个串后面的补齐字节都要给足（`L` 为偶数时 2+L+1 为奇数，需补 1 字节）。
2. 前两个串之后必须还有后继串，且后继串的起点严格小于载荷末尾。
3. `L` 与 NUL 位置一致，串内无 NUL。
4. 载荷长度 = 16 + Σ (L+4)&~1，不多不少。
5. 每个串不超过 255 个 UTF-16 码元。
6. h[0..5] 按 §5.2；类型和内容容器一致；页信封的 h[3]/h[4] 按“单页无工具→1，否则→3”。

## 6. 字符串与文本编码

### 6.1 编码

文件中的文本（页名、工具名、字体名、标签、说明、提示串、富文本块里的文字）统一使用一种编码，由 900 头 u16[11]（文本编码 ID）指定〔静态证据〕：

| ID | 语料 | 含义 |
|---:|---|---|
| 9 | 布局 5 的全部 1,410 个文件 | UTF-8（代码页 65001） |
| 3 | 布局 4 的全部 21 个文件 | Windows ANSI，代码页不记录 |
| 其它 | 无 | 原版内置一张“编码 ID→代码页”表（约 90 项）；没有语料 |

〔已验证〕布局 5 文件中所有文本都能严格按 UTF-8 解码。布局 4 文件中的非 ASCII 文本，20 个文件按 GBK 解码，1 个文件（`example-39.gsp`，页名）是 Big5。布局 4 里的富文本块可能含被截断的双字节字符（`14 立几平台.gsp`），读取时不得因此失败。

〔静态证据〕原版对布局小于 5 的文件，在某个全局设置有效时用该设置代替 ID（设置的来源和中文版的默认值未查清）；ID 为 0 的老文件则按 9004 构建串里的平台字母判断（`_W_`→Windows，`_M_`→Mac）。

实现建议：布局 5 一律 UTF-8；布局 4 默认按 GBK 读，允许用户改选 Big5；M1 里字符串都是原始字节，不转码。

### 6.2 字符串在记录里的几种写法

| 写法 | 用在 | 结构 |
|---|---|---|
| NUL 结尾，补到偶数 | 1100、9004、9007、1201（偏移 2 起）、10044（偏移 26 起） | 字节 + `00` + 0 或 1 个残留字节，使载荷长度为偶数（1201 的残留可到 3 字节，见 §7.4） |
| u16 长度前缀 + NUL | 902 提示串、2005 标签、文本块（§8.7） | `u16 n` + n 字节 + `00` + 补齐到偶数 |
| u32 长度前缀 | 9009 | `u32 n` + n 字节 + 恰 3 字节残留（无 NUL） |

NUL 之后的残留字节没有语义，值不定（9004、1100、9007 各出现过 0、1、2、3、0xFF 等多种值），**必须原样保留**。写新串时填 `00`。

换行：9007 工具说明里的换行是 CRLF（`0D 0A`），语料中成对出现〔已验证〕；原版读入时会把 CR、LF、CRLF 都规范成 CRLF〔静态证据〕。提示串里的换行是单个 LF。

- +12 的颜色三字节直接就是 COLORREF；原版读入时不看 +15。

**样式字（布局 5）**：低 12 位是三个 4 位字段，`w0 = 位 0..3`，`w1 = 位 4..7`，`w2 = 位 8..11`；高 4 位恒为 0。读入时夹取：`w0 ≥ 4 → 1`、`w1 ≥ 3 → 2`、`w2 ≥ 4 → 2`，高 4 位非 0 也算被修改（报警告）。〔静态证据〕语料取值范围正好是 w0∈0..3、w1∈0..2、w2∈0..3，原版 5.06 新建的点样式字为 `0x0221`（w0=1、w1=2、w2=2），线段为 `0x0122`（w0=2、w1=2、w2=1）；语料里最常见的是 `0x0121`。三个字段各自的含义（线宽、线型、点大小等）〔未知〕：线类对象的 w1 为 2/1/0 时像实线/虚线/点线，点的 w2 像点的大小，但未经实验。

**样式字（布局 4）**：u16 枚举 0、1、2；读入时 ≥3 改成 1 并报警告。读入换算成三个字段：0→(1,1,1)，1→(1,2,1)，2→(2,2,1)。〔静态证据〕

写出（布局 5）：`样式字 = w2<<8 | w1<<4 | w0`；比例 = 浮点×65535，向零取整，取低 16 位；+15 写 0；+18 不写（新写的文件填 0 即可）。

状态：0..4 的含义、field04、+24、排序值以及样式字三个字段的语义留给对象规格（`spec/objects/`）去实验确定。

### 8.2 父对象表 2002

```
u32 count | u32 parent[count]       ; 长度恒为 4 + 4×count
```

- 约束外部 ID ≠ 0 的对象**必有**一条，约束为 0 的对象**必无**。〔已验证，400,744 个对象〕
- `count` ≥1（语料 1..750）。原版以 16 位计算元素数，所以不要超过 65534。〔静态证据〕
- 元素是同一容器里对象的序号：**1 起**，总是小于本对象的序号（父在子之前）；允许重复。〔已验证，954,264 个元素〕
- 页和工具区各自单独编号：页内按 2000 出现的顺序编号 1..N；工具区内同理，从 1 起。
- 原版保存时，先把页里所有对象按对象链的顺序依次编号 1..N，再按这个编号写 2002；不能保存的对象被丢弃，其后的对象重新编号。〔静态证据〕写出器需要保证父对象排在子对象前面。

### 8.3 约束附加参数 2003

- 只出现在 25 种约束的对象上：15、17、18、19、21、22、23、24、27、30、52、54、55、56、62、67、68、75、96、98、99、109、110、122、123。〔已验证〕其中约束 15 和 62 并非每个对象都有 2003，其余 23 种必有。
- 出现时位于 2002 之后、类专有数据之前。
- 载荷以 u32 约束 ID 开头的占 80%（63,094/78,269），其后是随约束而变的数据（double、整数等）；内部结构**未解码**，须原样保留。
- 尺寸见附录 B：除约束 62 外，每种约束的 2003 尺寸固定（15 有 12 和 20 两种）；约束 62 的尺寸 36–11,268 不等（变长）。〔已验证〕

### 8.4 标签 2005

```
u16 f[7]        ; +0..+13
8 字节          ; +14..+21
u16 n           ; +22  标签文字的字节数
n 字节标签文字  ; +24
00              ; NUL
0 或 1 个补齐字节   ; 使载荷长度为偶数，值不定
```

〔已验证，114,266 条〕载荷长度 = 24 + n + 1 或 24 + n + 2；NUL 位置正确；文字编码见 §6。

字段（语料取值）：f[0] ∈ {3,4,6,7}（疑为标志位）；f[1]、f[2] ∈ {0,1}；f[3]、f[4] 为有符号 16 位，缺省 (8, 5)〔推测：标签相对对象的像素偏移〕；f[5]、f[6] 恒 0。+14 的 8 个字节：78,561 条是同一残留串 `98 6E 12 C1 51 5C 61 41`，29,415 条全零，其余是各种 double 值（0.25、1.0 …）；〔未知〕，整体保留。

### 8.5 样式引用 2008

`u16`：本容器内 1203 条目的序号（0 起）。〔已验证〕可与 2005 同时出现，也可单独出现。

### 8.8 图片与标记记录 8000 / 8002 / 8004 / 9006

- **8004**：`u16`，本文档 1006 组里 1300 图片的序号（0 起），< 图片总数。仅主类 16，439 条。〔已验证〕

### 8.9 对象内记录的固定次序

对象的 2000 与 2007 之间，记录按这个次序出现，不重复〔已验证〕：

`2002` → `2003` → `23xx` → `2005` → `2008` → `22xx` → `8000` → `8002` → `9006` → `8004`

原版读取器依次读：2000、父表（约束非 0 时必须有）、2003、类专有数据、2005、旧版的 2006、2008、22xx，每一步后面都会处理 8000 及以上的额外记录（见 §11）；最后必须是 2007，否则报格式错误。〔静态证据〕

## 10. M1 读写要求

### 10.1 读取器必须

1. 接受全部 1,431 个语料文件和 5 个基准样本（`samples/baseline/samples`）。
2. 按 §2 切记录；遇到越界、魔数错、首尾记录不符、嵌套不平衡，报错并拒绝，不要猜。
3. 按 §3 建立“文档 → 信封 → 页/工具区/组 → 对象”的树；每条记录保存 kind 和载荷字节，保持出现顺序。
4. **不认识的记录原样保留**：挂在它所在的容器上（`doc`、`compat`、`group`、`page`、`tool`、对象），位置按它在兄弟之间的顺序记录。语料里没有未知 kind，但格式允许出现（§11）。
5. 已识别的字段按本文解码；未解码的字节留在载荷里不动。
6. 读取器应该记录每条记录补齐字节的原值（语料恒为 `00`，不为 `00` 时仍要能原样写回，或拒绝）。
7. 布局 4 文件：对象头 16 字节；文本按 §6 的编码选择；2306/2308/2309 的尺寸与布局 5 不同（§8.7）；没有 1006、2418、2419、10005–10008、10023、10044、9009。
8. 文件末尾 901 之后如果有多余字节，作为尾部块保留（语料没有这种文件）。

### 10.2 写出器必须

1. **对未修改的文档，写出的文件与原文件逐字节相同**，包括：记录次序、每条载荷（含 §9.2 的残留字节）、补齐字节、900 头、信封里的串。
2. 载荷长度字段 = 实际载荷字节数；奇数长度后补一个 `00`。
3. 修改文档时，下面这些量要按新结构重算，不能沿用旧值：

   | 字段 | 规则 |
   |---|---|
   | 900 头 [1]、[2]、[12]；[8] | 页数、工具数、信封总数（布局 5）；活动页序号 |
   | 902 头 h[3]、h[4]（页信封） | 单页且无工具 → 1，否则 3 |
   | 1000/1002 头 +24 | 容器内 2000 的个数 |
   | 2002 的元素 | 重新编号后的父序号（1 起，小于本对象序号） |
   | 1204 | 工具已知对象的序号表 |
   | 2008、1203 [0]、8004 | 指向 1203 / 1201 / 1300 的序号 |
   | 9000、9005 | 指向页内对象的序号 |

4. 新建内容的缺省字节：
   - 新建文档的记录序列，以基准样本 `samples/baseline/samples/empty.gsp` 为模板（附录 D 列出了页前导）。
   - 残留字节填 `00`；9004 照抄 `GSP5_w_1074K/Apr 19 2013`；9008 取 96。
   - 新对象的对象头：布局 5，比例 `0xFFFF`，+20 排序值 `0xFFF0BDC1`，其余 0；样式字与颜色取原版 5.06 的缺省：点 `0x0221` + COLORREF `FF 00 00`（红），线段 `0x0122` + `00 00 80`（深蓝），中点同点；其它类对象的缺省留给对象规格。
5. 不要写布局 4（M1 之内只读）。

### 10.3 检查

`tools/check_gsp_grammar.py` 是这份规格的可执行版本：对任意目录运行 `python -I tools/check_gsp_grammar.py --root DIR`，有违例就非零退出。实现方可以用它检查自己写出的文件是否仍然合规。注意它检查的是**本文总结出来的文法**，是语料的子集约束，不是原版读取器的全部容忍范围。

## 11. 原版读取器对未知内容的处理〔静态证据〕

这一节说明原版遇到不认识的内容时怎么做，用来判断“写什么原版不会崩”。

| 层级 | 行为 |
|---|---|
| 文档（900 内） | 每个成员必须是 902，否则报格式错误；信封内容按 §5.4 判定 |
| 附加信息组（1006 内） | 只处理 1300；其它 kind 跳过；以 1007 结束 |
| 页前导区（1000 之后，第一个 2000 之前；以及对象之间、最后一个对象之后） | 认识：1100、1101（忽略）、1200（旧版）、1201、1203、9000、9001、9003、9005、9007、9009、2399–2490、10001–20009（偏好读取器，不认识的忽略）。其余按 kind 分：8000–8999 → 跳过并报“可能丢失信息”警告；≥9000 → 静默跳过；<8000 → 视为前导区结束，若不是 2000 或 1001 则格式错误 |
| 对象内 | 次序见 §8.9。额外记录区：9006 清标志；8000–8004 只有主类 16 会解析，其它主类遇到则警告并跳过；8005–8999 → 警告并跳过；≥9000 的不认识的 → 静默跳过。最后必须 2007，否则格式错误 |
| 约束/主类/genera 外部 ID 无效 | 对象无法读取：跳过其全部记录到 2007，报“无法读取”，文档作为副本打开 |

语料里没有、但原版读取代码认识的 kind（〔静态证据〕，M1 读到时当不透明记录保留即可）：

| kind | 位置 | 读取行为 |
|---:|---|---|
| 1004、1005 | 类型 3 信封内 | 文档二进制块，见 §5.8 |
| 1101 | 页前导区 | 读入时跳过 |
| 1200 | 页前导区 | 旧版（元数据版本 1）标签计数表：13 行 × 6 字节 |
| 2006 | 对象内，2005 之后 | 旧版对象记录 |
| 2199 | 对象内 | 22xx 的旧版替代 kind（自由对象位置记录接受 `2200+主类` 或 2199） |
| 9001 | 页前导区 | u16 页标识，读入时最高位置 1 |
| 9003 | 页前导区 | 页调色板条目：u16 序号（<9）+ R,G,B（从偏移 2 起，格式同 10020） |

由此得到几条对写出器有用的结论：

- 页内新增记录应使用 **≥9000** 的 kind（老版本静默跳过），对象内新增记录同理；8000–8999 会让老版本弹警告。
- 不要在页前导区里写 <8000 的未登记 kind：老版本会认为前导区在此结束。
- 新功能的大块数据放进新类型信封（§5.4）。
