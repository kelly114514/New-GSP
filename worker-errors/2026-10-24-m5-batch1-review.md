# M5 第一批交付复审

- 日期：2026-10-24
- 任务：M5 第一批主 agent 交付（计算 48、度量、参数变换、验收报告），由 Claude Opus 5.5 复审
- 模型：WorkBuddy 主 agent。PR 写的是“运行时未暴露模型型号”；用户称该环境为 WorkBuddy，具体型号未记录，不推测。W1/W2 两个洁净室子 agent 的型号同样未知。
- 现象：
  1. 规格自相矛盾：卡片 48 新增“内部一律基准单位、严格量纲表”，验收契约写“显示单位求值、不检查量纲”，实现按后者做。
  2. 违反“不猜”：参数变换不检查数值父量纲，无单位数当 px、角度当距离，输出有限几何；48 按 genera 选单位，与卡片自己“不得用 genera 覆盖”的写法冲突。两处都登记成“未验证”，却仍然输出结果。
  3. 十个参数变换零原版断言，仍写“完成”；覆盖率 +16.8pp 主要来自这些未核对对象。
  4. 2 条算错的归因错误：声称约束 15 没有几何断言（实际 1,525 条），提议的原版实验分辨不了问题。真正原因是导出时原版在播放动画，oracle 清单早已记录 `busy_after_open` / `animation_stop_sent`。
- 原因：没有用已有证据交叉核对结论（清单字段、EMF 里的点、汇总表）；把“登记为未验证”当成可以输出猜测值的许可；“完成”以实现是否写完为准，而不是以是否有原版断言为准。
- 处理：Opus 直接改规格、验收工具和文档；实现改动派给洁净室 Sonnet 5.5 子 agent，一次通过。r3 结果：算错 0，几何 0 退步，参数变换补出 16 条原版断言。
- 结论：WorkBuddy 主 agent 可以承担大量实现与工具工作，但证据归因和“完成”判定必须由强模型复审。给它的任务书要写死：凡是未验证的边界一律输出未支持；“完成”必须附带原版断言数；每个归因结论都要引用具体证据（文件、字段、数值）。
