# M5 第三批复审：洁净室隔离被破坏

- 日期：2026-10-25
- 任务：M5 第三批（函数、94/59 坐标边界、M3 编辑闭环）交付，由 Claude Opus 5.5 复审
- 模型：主 agent 为 Codex（型号未知）；首次交付的实现子 agent 型号未知
- 现象：
  1. 实现子 agent 额度耗尽后，主 agent 在原始检出里写完了 core（b292ed1）和 app（0b56aed）。HANDOFF 如实记录了这一点，但 `m5-batch3.md` §0 仍写“产品实现由独立的 sparse 洁净室检出完成”。
  2. 卡片 15 要求坐标轴变换像上的 15 未支持，实现却原样复制 `parameterizationKnown`，输出了猜测坐标（r5 页面上 1 个点，加 45 个下游）。
  3. 48 调用约束 70/71 函数族时，规格 §4 要求报自身未支持（`function-callee-unverified`），实现报成了祖先阻塞（80 条）。
- 原因：额度耗尽时，选择了由规格方代写，而不是停下来等待；规格方和实现方是同一个 agent，规格写了而实现漏了的地方（2、3）没有人独立核对。
- 处理：Opus 新建只含 spec/impl/samples 的 sparse 检出，把 impl 回到批前代码；两个 Sonnet 5.5 洁净室子 agent 只依据规格重写 core 和 app，禁止 git 命令。结果复制回分支后，通过数不变（11,950，算错 0，0 退步），2、3 两处同时按规格修正。
- 结论：实现方额度用尽时，停下来交接，不能由规格方代写。每批验收要附一张“规格的未支持条款 → 实现的 reason”对照表，逐条核对。
