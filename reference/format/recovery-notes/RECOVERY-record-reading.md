# 分段记录读取与连续缓冲拥有权

完整恢复 `004BA220` 记录头读取、`004BA370` 连续载荷读取、
`004BAAB0` 流长度和 `00549810` FILE 长度探测。
生产实现只使用恢复的字节I/O、分页表、分配策略和显式CRT接口，不执行原PE。
原始查询在 `analysis/sessions/record-reading/`，完整原字节/Listing/重定位清单在
`tests/fixtures/record-reading/`；实际使用的函数边界以夹具为准。

## 布局与行为

`StreamState32 +10` 是连续读取缓冲指针，`+14` 是其分配字节数。
保留原 `field_10` DWORD 名字，并以同布局 union 增加 `record_buffer_10`，
使分配策略可操作真实指针单元，不把局部指针冒充原地址或违反指针别名规则。
`004B8FD0` 已恢复的关闭路径负责释放该缓冲。

`004BA220` 从当前位置依次读取raw长度与kind两个DWORD。成功依次写出physical长度、
可选raw长度、可选kind；输出地址重叠时也保留此顺序。physical长度按流 `+4` 标志
决定是否向偶数字节取整，保留32位溢出。与 `004BA0D0` 不同，这个函数不回滚位置；
失败保留已读内容/位置，将状态写入当前注册表中的stream sticky error。
原局部字节在读入前未初始化；type4不提供数据的后端仍不构成有效记录头输入。

`004BA370` 的长度为physical长度：

- 零长度直接返回，输出指针保持原值，不能假设空记录会把它清零。
- 大于FFFFh时尝试流长度与当前位置探测。两者都成功且长度/终点越界时，
  先尝试seek到流尾，再返回25；seek的状态不覆盖该返回，也不另写sticky25。
  任一探测失败则继续原分配/读取路径。终点加法按原32位运算，未另加64位规则。
- 首次通过真实 `0043CB30(length,0)` 分配；不足时用 `0043CBE0(...,length,1)`
  扩容。原分配策略的reserve释放/重试仍真实执行，没有原样搬运payload或成功回调。
- 扩容时保留原stream指针写 `+14`；之后取缓冲、实际读取和成功输出均按原位置
  重读 `006BB560` 注册表slot。回调改变slot时不能将这些查找合并。
- 成功返回stream所拥有的借用缓冲；下次调用可覆写或搬移，关闭会释放。
  对象读取器必须消费/转换其中数据，不能将它直接当作对象持久payload取得拥有权。
  失败将错误写入新查找的stream并保留输出指针原值。

`004BAAB0` 对非FILE流返回 `+20` logical_end；FILE调用真实 `00549810` 算法：
清errno、保存ftell、清errno、seek尾、ftell尾、seek回保存位置，最后提交长度。
首ftell为-1且errno为零仍继续；尾ftell为-1直接进入错误映射；中途失败不额外补回滚。
标准FILE/errno通过已有显式宿主适配提供，原静态CRT布局及全部异常语义仍不宣称恢复。

## 验证边界

1,171字节夹具执行这四个完整原函数。原码的底层字节I/O、注册表、分配策略、
tell/seek和errno映射调用两侧共用的另行验证实现与受控CRT边界，不能重复宣称
对这些依赖独立差分。未知调用立即终止，没有应用层成功替身。

55组头读取、48组载荷读取及12组长度探测比较完整stream/注册表、输入/缓冲字节、
错误/输出以及全部受控CRT/分配调用轨迹，覆盖偶数对齐与32位溢出、输出别名、
截断、已有错误、缓冲复用/搬移/失败、大记录越界、长度探测失败继续读，以及
malloc/realloc/read引发注册表slot切换。

真实MSVC FILE集成写入空记录、奇数记录和70,000字节记录，关闭重开后用本模块
读取，检查padding、增长缓冲、EOF及关闭释放。此验证只证明记录与缓冲拥有权；
对象typed转换、load-map、父引用修复、页面/文档解释和GSP双向开存仍未贯通。
