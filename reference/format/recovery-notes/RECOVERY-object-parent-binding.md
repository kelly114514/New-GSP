# 建立对象父子边

`00441920` 接受新对象及已分配的父向量handle，使用当前页/可搬移arena。
生产实现调用真实恢复的 `004D5870/004D5790/004D5AD0`，不调用原PE。

函数先递增页面 `+28C`。父handle为零或父向量count为零时，释放传入的空向量，
将对象 `+AC` 置零并返回1；否则将该handle转入对象 `+AC`，按顺序将对象指针
追加到每个父对象 `+B0` 的子向量，包括重复父边。每次追加后重读arena基址；
父对象本身保持稳定，父向量可能随arena扩容搬移。调用者不能继续拥有传入handle，
也不能以此函数覆盖另一个仍由对象拥有的旧AC向量。

## 原版失败行为

第一次子向量追加就失败时，函数释放父向量、清空对象AC并返回0。
若已有至少一次成功追加，原 `004419E0..00441A3D` 回滚循环固定访问第一个父对象，
既不推进父索引，也不在其子向量count降为零后退出。它会进入无限循环；后面的
`00441A3F` 清理分支在该路径不可达。源码保留实际控制流，没有把此状态伪装成
回滚成功，也没有悄悄修复原版缺陷。

测试使用40字节arena：父向量及第一个子向量分配成功，第二个子向量触发扩容失败。
失败输入适配先检查第一个父对象已拥有一条真实子边，再通知看门狗。原码和恢复
实现分别在一次性子进程中运行，均在就绪后300ms内不返回，由父测试进程终止并
回收。该运行观察与完整Listing中的无出口控制流共同支持上述判断；没有让统一
CTest进程陷入循环。此行为属于原版已存在的异常路径，后续M1错误验收需单列。

## 验证范围

318字节完整原函数按原件哈希绑定，Listing/地址/重定位见
`tests/fixtures/object-parent-binding/`。7组差分比较全部页、对象、两个arena缓冲、
返回值、扩容请求和当前基址，覆盖空handle/空向量、单父、多父、重复父边、真实
搬移和首次追加失败清理。另有两次隔离的部分失败卡住观察。

oracle的arena callees使用另行完成原码差分的恢复实现，是共享依赖，不重复宣称
独立验证其算法。对象挂链/释放集成的共享父点→线段→中点引用图已改用本函数
建立双向边，随后运行真实解绑与向量释放。原构造器的父模板合法性、样式、类型
payload、求值及标签初始化仍未完成，本函数不能代表整个对象构造器。

REA函数证据位于 `analysis/sessions/object-parent-binding/bind-parents.json`。
