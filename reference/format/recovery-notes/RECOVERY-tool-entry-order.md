# 工具条目排序（00484010）

`src/tool_entry_order.cpp`恢复原函数`00484010..00484087`，排他上界`00484088`，共120字节。
目标身份与字节由`tests/tool_entry_order_extract_fixture.py`按SHA-256核对解包中文主程序，
完整LLVM Listing在`tests/fixtures/tool-entry-order/original.asm`。`analysis/sessions/read-path-leaves`
中的Ghidra伪代码只作线索，地址、比较宽度与分支以Listing为准。

## 原函数行为

- 输入：EDI为上下文指针，无栈参数，无返回值。
- 清寄存器：EAX、ECX、EDX与标志；保留EBX、ESI、EDI、EBP。函数内部调用为零，不需要桥接或替身。
- 原函数先读上下文`+0x5C0`（有符号）：`<=1`直接返回，不读取任何对。
- 之后对数组`+0x5B8`（8字节对，`{对象指针@+0, 值@+4}`）做冒泡：相邻两对中，前者对象`+0x48`为0且后者对象`+0x48`非0时整对交换，并置交换标志；内层每次迭代后重读`+0x5C0`，循环条件为有符号`i < count-1`；外层以标志决定是否继续。
- 对象指针解引用无空检查；空指针是原码访问冲突，恢复实现保持同样的无检查行为，不作为成功情形测试。

`004A99E0`中的写入位置由Listing得到：`004A9AEC`写`+0x5B4`、`004A9AF6`写`+0x5C4`、

这些字段的语义以Listing为准，`004A99E0`本身未恢复，也不在本模块范围内。

## 恢复实现

- 比较宽度：全部为32位有符号比较（`jle/jl/jbe`对应的有符号分支）。`+0x48`只做与0的比较。
- 指针：对象指针为32位，`ToolEntryPair32`大小8字节，`static_assert`保证布局。
- 循环：内层`do/while(index < count-1)`，每次迭代后重读`count`；内层界`count-1`按原`leal`的32位回绕计算。
- 每一轮外层开始都执行原码`484030..484039`的`count-1 <= 0`返回，所用`count`是上一轮最后重读的值；`count<=1`与`addl $-1`+`jle`的标志判断等价（含`0x80000000`溢出）。因此计数为负数或0时不解引用。
- 交换按原码`484050..484063`的读写次序：先存前者对象，再读后者值，然后写后者值、前者值、后者对象。对数组与上下文或自身重叠时次序可观察。
- 调度者审查修正：worker初版只在进入时检查一次`count<=1`，外层之后无条件再做一轮。若某次交换改写了`+0x5C0`使其`<=1`，原码就此返回，初版会多做一轮并继续交换（构造的重叠场景中初版写坏计数后越界访问而崩溃）。差分新增两例：对数组起于上下文`+0x5B4`，使`pairs[1].value`即`+0x5C0`，交换写入计数1或0，比较完整内存。

## 测试替身与适配

- 测试替身：无。生产源码不包含原机器码，不调用原EXE。
- 差分中的原码执行：`invoke_original`为naked桥接，将EDI设为上下文并按原ABI调用字节拷贝到RX页的原函数。
- 适配：`ToolEntryContext32`只是字段偏移的最小覆盖，不是完整页对象。

## 差分测试

- 原码与恢复实现在同一个内存快照上各执行一次，比较整个内存区域（上下文0x5E0字节、对象体、对数组容量区）。
- 参考模型独立计算：只交换“零键在前、非零键在后”的相邻对，因此最终结果为对前缀的稳定划分（非零在前，零在后，同类相对顺序保持），计数之外的槽位不变。
- 覆盖：计数为0/1/负数/INT_MIN（含空对数组）；2至8项全部零/非零模式，每种有或无额外容量；全零、全非零、交替两种、已排序、逆序、单个错位；重复对象与对象内存顺序不同于对顺序；200个固定种子随机序列（长度2至64）。
- 具体用例数以`manifest`中的测量记录为准，由测试输出`tool_entry_order differential PASS: N cases`给出。

## 限制

- 不证明`004A99E0`的完整语义，也不恢复其调用的记录读取（`004BA220/004BA370`）与分配（`0043CB30`）。
- 对象`+0x48`之外的字段不是本模块的语义；对象的其它字节只在差分中保持不变。
- `0043CB30`以EBX传字节数、栈上传类别的约定为由Listing推断，未独立验证，本模块不依赖它。
- 空对象指针、对象地址越界等原码的访问冲突行为不测试，恢复实现同样不做检查。
