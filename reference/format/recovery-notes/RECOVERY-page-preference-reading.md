# 页面偏好记录读取

`page_preference_reading.cpp`恢复原始`00494FF0..00495378`（读取一条页面偏好记录并按kind写入偏好结构）
与`004375A0..004375EE`（10个16位字复制）。目标身份、每段字节和SHA-256由
`tests/page_preference_reading_extract_fixture.py`从解包中文主程序核对，完整LLVM Listing在
`tests/fixtures/page-preference-reading/original.asm`。`00494FF0`函数体之后紧跟两张分派表
（`0049537C`的16个dword目标、`004953BC`的43字节索引），抽取范围`494FF0..4953E8`包含它们。

## ABI

- 进入：`ECX`=流句柄（保存到`ESI`，作为`004BA220`的流参数），`EBX`=偏好输出结构（`FC`字节块，
  原函数不保存`EBX`而直接写入）。返回：`EAX`=状态，成功为0。
- `004BA220`的原ABI：`ESI`=句柄；栈上依次为kind输出、raw长度输出、物理长度输出（三者都必须存在）。
- `004BA370`的原ABI：`ESI`=物理字节数；栈上为句柄与payload输出指针，输出是流自有缓冲的借用视图。
- `004EA0B0`的原ABI：`ECX`=字体WORD输出（风格行首WORD），`EDX`=序列化字体载荷（偏移0x18处）。
- `004375A0`的原ABI：`EAX`=源，`ECX`=目的；无返回值。
- 生产实现的规范化签名为`FUN_00494FF0(stream, preferences, environment)`，
  `FUN_004375A0(source, destination)`；寄存器语义由测试的汇编桥接验证。

## 分派与布局

偏好结构布局与`page_preference_write`一致（`PageDefaultState32::preferences`，0xFC字节）。
读取写入的字段（偏移均为原函数写入的地址）：

| kind | 原分派 | 条件 | 写入 |
|---|---|---|---|
| 2712..2718 | 布尔，索引`kind-2712` | raw==2 | `(kind-2712)*4` 处写32位0/1（载荷WORD非零） |
| 2726 / 2727 | 布尔 | raw==2 | `0E0` / `0E4` |
| 2724 | 颜色 | raw>=6，索引<15 | `0A0+索引*4` 写`R | G<<8 | B<<16`（载荷字节2,3,4） |
| 2725 | 钳位整数 | raw==2 | `0DC` 写min(WORD,16) |
| 2738 | 三槽低字节 | raw==2，高字节<3 | `0E8+高字节*4` 写低字节 |
| 2739 / 273A | 槽值 | raw==2，WORD<3 | `0F4` / `0F8` |
| 273C | 风格行 | raw>=1CH，索引<6 | 行基址`1C+索引*22`：先复制10个WORD（载荷+4），再以字体转换结果覆盖行首WORD |

分派表在编译产物中为字节索引`004953BC`（43项，对应kind 2712..273C）加dword目标表
`0049537C`（16项，索引0x0F为默认分支`495353`）。未列入上表的kind（2719..2723、2728..2737、273B、273D..273F）
走默认分支。生产代码用`switch`重写同一映射，映射由差分测试覆盖全部范围与边界。

## 错误路径与原语义

- `004BA220`或`004BA370`返回非零时，原函数不写任何字段，直接返回该状态。
- 长度不符（布尔raw!=2、颜色raw<6、风格raw<1CH）或索引越界时，原函数**返回0且不写**，
  记录被消费；这是原码语义，不是错误码。
- 默认分支：kind在`2711..501F`（含分派表外的合法区间）返回0并消费记录；其它kind返回`1E`，不写。
- 分派所需的载荷指针恒有效：raw>=2时物理字节数>=raw>=2，`004BA370`必然设置payload。

## Cookie 与替身

`00494FF0`开头与返回前的`__security_check_cookie`（`005EDDAA`，cookie全局`006A499C`）是MSVC栈保护，
不属于恢复的函数体语义。原始字节测试中：绝对操作数`006A499C`重定位到测试变量，
`call 005EDDAA`重定位到测试桩（比较ECX与测试cookie）。生产源码不实现也不调用它。

## 测试范围

`page_preference_reading_differential.cpp`的原字节oracle直接执行`00494FF0`及其`004375A0`复制，
所有调用重定向：`004BA220`/`004BA370`/`004EA0B0`接入已恢复的生产实现（`FUN_004BA220`、
`FUN_004BA370`、`FUN_004EA0B0`），`005EDDAA`接cookie桩。每次比较对同一快照分别运行原码与生产实现，
比较返回状态以及整个测试状态（流表、存储、记录缓冲、分配计数、偏好结构全部字节、测试canary）。

覆盖：全部布尔kind与值类；布尔与颜色的长度不符（含零长度）；颜色索引0/1/14与15/0xFFFF；
2725的钳位边界；2738的槽高字节0..3与低字节；2739/273A的边界；273C的多种字体名（别名、UTF-8、空串、超长名）、
索引5/6/0xFFFF，以及raw=1BH的短行；分派外kind与分派内未用kind；头部错误、sticky错误、截断载荷、分配失败；
未对齐流（`align=0`）；连续记录顺序（触发缓冲resize路径与EOF）；以及`analysis/unpacked`样本`point.gsp`的
36条真实偏好记录（真实文件读取后回放给两种实现）。

输出行：`page preference reading PASS: N original differential cases; ...`。

## 适配与限制

- 生产路径不调用原EXE，不使用测试替身；原码oracle仅在测试中存在。
- 分派使用`switch`代替编译器跳转表，映射已对照表项验证。
- 字体转换依赖`004EA0B0`的前置条件：`payload+1AH`起的名字必须在记录内有NUL结束。
  生产代码与原码一样不检查该前置条件；越界读取属于调用者的契约。
- `004BA370`分配的记录缓冲由测试提供的分配环境计数；`00494FF0`自身不分配也不释放。
- 测试状态中的`scratch`和`storage`是测试替身，只用于观察缓冲行为，不属于生产代码。
- 不含`00437550`/`00493D40`写侧（已由`page_preference_write`恢复）。
