# 最小真实对象记录读取

`read_minimal_object32` 是对现代格式 `004A9300` 所选路径的明确生产适配，
不计为完整原函数恢复。来源是
`analysis/sessions/minimal-document-io/load-object.json`
（`ev_643d088a4aa4047907d789988db00318b7b395a2eb7932e330794bbd800afd82`），
以及同目录的完整 `load-object.asm`。
父读取、typed装配、header/点转换、对象创建、父子边和释放均调用现有真实实现；
生产没有原PE执行，也没有未恢复成功callback。

## 支持范围与调用链

输入页必须是已有生产页构造器创建的当前无窗口页，`006BA20C=0`、页+560非零，
原生arena有效；分配器必须保持上下文且不重入。对象map含保留的slot0，
目标ID须有效且为空。只接受metadata `word0=2, word2=5, word3=5` 的现代格式，
header必须恰为28字节。旧格式与需要未恢复palette转换的路径明确拒绝。

支持的 `constraint/kind/genera/parent-count` 为自由点 `0/1/4/0`、
线段 `2/2/14/2`、中点 `1/1/11/1`，field08限0/1。消费顺序对应原始地址：

- `004A9363..004A9376`：2000记录由 `004A89C0→0043D190→0043CD70` 读取。
- `004A93DF..004A93ED`：约束对象2002记录由真实 `004A8D70→004A7220` 读取，
  ID转换为现有map中的对象指针。父必须是更早ID且已经属于本页；前向/空/越界
  引用和类型不匹配均拒绝，不插入NULL父对象或成功占位。
- `004A95CC..004A95EF`：已有最小构造器真实创建、绑定父子边、默认样式与内部短标签、挂链。
- `004A9610..004A9614`：按原对象读取器恢复header颜色到+2C。
- `004A977A..004A97D0`：自由点2201载荷必须恰为16字节，调用
  `004A8C60→00445F30→00445EE0→00445E10`，转换binary64坐标并真实更新缓存，
  然后设置原生+CC为1。线段与中点没有此记录，+CC保留0，几何仍待求值。
- `004A9895..004A98C5`：必须是空2007尾。完整对象成功后才按
  `004A999B..004A99A8` 把指针提交到map。

2003 extra、2005/2006/2008样式/标签、动态payload及>=8000属性记录在各个
读取位置均明确拒绝。此适配未调用这些路径的成功替身，也未复制原payload
充作持久模型。后续样式模块可扩展准入，但不能将被跳过的数据称作已支持。

原 `004A7220` 对序列化count保留原生backing-storage前提，`004A8D70`
对raw=0还有16位减法语义。适配在调用前用真实头/载荷读取预检：raw必须是
预期 `(parent-count+1)*4`，载荷count与类型完全一致，ID必须有效。通过后seek
回该记录起点，再由完整父读取器实际分配原生向量并解码。这是新增的有界准入，
比原路径多一次读取；不宣称畸形输入下逐字节复刻原生未界定行为。预检期间输入
文件必须稳定，分配器/stdio不重入或替换输入。

## 拥有权与失败

父向量归属在构造器准入前由适配持有。header/父记录失败、未支持记录或构造准入
拒绝时以 `004D5790` 释放；构造一旦准入，按已有构造器合同消耗该向量。
对象创建后的载荷/尾失败调用真实最小销毁器，反向解绑、从页面/分类环移除、
释放对象及其向量。已有父对象的空子向量仍为页面拥有，整页释放负责收尾。
失败不提交map；原有对象和map保持拥有权。原label序号及页修改计数的合法副作用
不会被伪装成原子回滚，流进度也不额外回退（父预检成功的显式回放除外）。

arena扩容转接在callee继续前发布移动基址到 `006BBA54`；构造返回再重读该全局，
同步页+18C缓存。没有把uint32全局别名成 `void**`。allocator改变当前页的违反
合同情况单列cleanup_failed，不当作正常失败清理完成。
已知原 `00441920` 在部分子边建立后再arena扩容失败时有不退出的回滚缺陷，
本入口仍使用该原函数恢复实现，不宣称已经修复原件缺陷。

## 已验证的层次

独立命令：`recovered/native/tests/minimal_object_reading_build_probe.ps1`，
使用现有MSVC x86静态库与新增生产模块，`/O2 /W4 /WX /fp:strict`。

实际磁盘打开Q1的5件原版UI生成/重开样本，逐件校验完整SHA256。
空样本只验证实际流/页生命周期；另4件从Q1证据中已确认的首对象偏移1744开始，
总计真实读取12个对象。检查原生kind/constraint/genera、header样式/颜色、
双精度坐标/缓存、map身份、链表次序、父顺序与反向子边；随后真实整页释放，
所有堆分配归零。

16个失败场景覆盖未支持的头/类型/样式/尾、短header、旧格式、载荷/尾截断、
原生对象分配失败、父raw=0、count不符、零/前向/未映射ID，以及线段构造后
尾失败的真实父边回退。另由原始对象记录构建302对象共享父图，测试分配器强制
arena搬移，核对所有父向量、父的300个反向子边、当前arena与页面缓存；逆序
生产释放最终归零。这是验证新集成搬移风险的场景，不作为新增功能计数。

这里没有读页面前导、页成员/样式表、文档头尾或页后处理，因此不称为整份GSP
读取或双向开存验收；约束对象坐标未求值，亦不称为M2动态几何完成。
数值使用显式宿主floor/integer适配，测试限普通有限坐标，不覆盖原静态CRT
全部异常数值行为。完整原004A9300机器码差分尚未执行；本模块的原函数依赖已
各自差分，本适配验收层次为所声明范围的真实集成。
