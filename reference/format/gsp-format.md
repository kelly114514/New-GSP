# `.gsp` 静态文件结构调查

调查日期：2026-10-18（Asia/Shanghai）。范围：`C:\projects\逆向几何画板\sketchpad5` 内全部扩展名大小写不敏感的 `.gsp`。仅按字节读取，没有启动几何画板、执行仓库内程序、修改克隆仓库或切换 REA 活动目标。本报告是本地静态脚本证据，不冒充 REA 反编译或运行时证据。

## 已确认的字节布局

1,431 个样本共 59,994,160 字节，SHA256 全部不同。最小 2,208 字节，最大 1,107,976 字节，中位数 17,020 字节。完整路径、大小和 SHA256 见 `gsp-inventory.json`。

**全部样本以 `47 53 50 34`（ASCII `GSP4`）开头，随后是一组小端、2 字节对齐的记录。** 此布局在 1,907,414 条记录、84 个不同 kind 上全部精确抵达 EOF，没有越界、剩余字节或未识别的文件尾。

```text
file[0:4] = "GSP4"
record at p:
    u32le payload_length @ p
    u32le kind           @ p + 4
    byte[payload_length] @ p + 8
    如 payload_length 为奇数，随后补 1 个 00
    next_p = (p + 8 + payload_length + 1) & ~1
```

长度仅计算 payload，不含 8 字节记录头和补齐字节。所有样本首记录均为 `kind=900, length=28`，末记录均为 `kind=901, length=0`。全部存在的 457 个补齐字节均为 `00`。

对照实验：相同算法去掉补齐会失败 290 个文件；按 4 字节对齐会失败全部 1,431 个文件；将长度和 kind 当大端，全部在第一条记录 `0x04` 即越界。因此，这不是只在少量样本上偶然成立的切分方式。

## 结构与字段关联

以下“数值关系”均对整个样本集验证；“页面、对象、依赖”等名称仍是语义推断，尚未与反编译出的读写函数或实际 UI 核对。

| kind 或字段 | 直接观察 | 语义候选 |
|---|---|---|
| 900 / 901 | 每文件各一次，首尾出现 | 文档开始 / 结束 |
| 902 / 903 | 各 4,973 次；902 可带兼容性提示文本，903 payload 均为 0 | 带版本或扩展兼容信息的容器 |
| 1000 / 1001 | 各 2,455 次；1000 payload 恒为 36 字节，1001 为 0 | 页面开始 / 结束 |
| 文件 `0x0E` 处 u16le | 每文件值严格等于本文件 1000 和 1001 各自出现次数，范围 1—38 | 页面数 |
| 1000 payload `+24` 处 u32le | 对全部 2,455 个 1000/1001 区间，值都等于区间内 kind2000 的数量 | 页内对象数 |
| 2000 / 2007 | 各 400,744 次，2007 payload 恒为 0 | 对象开始 / 结束 |
| 2002 | 全部 370,457 条均满足 `length = 4 + 4 * first_u32le` | `u32 count + u32[count]` 的依赖索引/引用向量 |
| 2201 | 17,760 条，payload 恒为 16 字节 | 两个 IEEE-754 小端 double 的位置/坐标 |
| 9004 | 每页一次，常含 `GSP5_w_.../日期` 等 NUL 终止 ASCII 字符串 | 保存来源/构建标记，不能据此判定当前 exe 版本 |
| 1300 | 370 条，均为 `u32le width, u32le height, 完整 PNG` | 嵌入图片；UI使用方式待核对 |
| 1100 | 1,910 条，其中802条在1000/1001区间内，1,108条在其外 | 页面名称或工具名称文本候选 |

将以下记录对作为栈结构检查，全部文件都嵌套闭合，错配为 0：`900→901`、`902→903`、`1000→1001`、`1002→1003`、`1006→1007`、`2000→2007`。这支持“带显式结束标记的层级记录”解释。`1002/1003` 和 `1006/1007` 的业务语义仍未知。

2000 与 2007 之间可以出现 2002、2003、2005、2008、2201、23xx、90xx 等记录；并非所有对象都有相同子记录。不能仅凭 kind 名义数字把它们当作单一固定 C 结构体。

## 两类布局与文本编码

文件绝对偏移 `0x0C` 的 u16le 有两类：值 5 的 1,410 个文件；值 4 的 21 个文件。它与对象头长度严格对应：

| `file[0x0C:0x0E]` | kind2000 payload 长度 | 记录数 |
|---|---:|---:|
| `05 00` | 28 | 360,923 |
| `04 00` | 16 | 39,821 |

由此可将此字段用作**布局版本候选**；现在还不能断言它就是界面显示的主版本号。特别是两类文件的 magic 都是 `GSP4`，目录名 `4.x实例` 或 `5.x实例` 也不能替代实际头部检查。

文本并非全库统一编码：

- 最小样本的 `0x40` 是 u16le 120，`0x42` 开始的 120 字节可严格按 UTF-8 解码为：“本文档中的一些新增信息是由一个新版本画板创建的，无法读取。该文件将打开一个副本。”
- 旧布局样本 `卫星.gsp` 的 `0x44` 是 u16le 44，`0x46` 开始的 44 字节可严格按 GBK 解码为：“此文档是由新版本的几何画板创建的，无法打开。”

这只确认这两个文本字段的编码；没有证明其他字符串都遵循相同编码选择规则，也没有实际触发这些提示。

kind9004 中共观察到 13 种 ASCII 构建字符串，包括 `GSP4_W_0516/Aug  7 2002`、`GSP4_W_0594/Aug 28 2006`、`GSP5_m_0948K/Oct 26 2009`、`GSP5_w_0984K/Apr 28 2010` 和 `GSP5_w_1074K/Apr 19 2013`。准确次数、首个示例记录偏移和 payload 原始十六进制见 `gsp-structure.json`。读取此字段应在首个 NUL 截断；NUL 后可能还有其他字节，不应把整个 payload 当作纯字符串。

## 压缩与嵌入资源

观察：全部文件都能直接分出上述明文记录头，文件头不是 ZIP、gzip 或 OLE 容器头，因此无须先对整个文件解压才能读取记录。**这不排除某些 payload 自身压缩。**

370 条 kind1300 记录分布在 204 个文件中。逐条检验 PNG 签名、每个 chunk 长度和 CRC、IEND 边界，370 条全部通过；每条 PNG 都恰好从 `payload+8` 开始、在 payload 末尾结束，前两项 u32le 都与 PNG IHDR 中的大端宽高一致。

例如 E 的 `0x019A` 为 kind1300，payload 长20,848，`0x01A2` 和 `0x01A6` 分别为小端128，PNG 在 `0x01AA` 开始，IHDR 宽高为128×128。该记录可结构化为 `u32le width, u32le height, png_bytes`，不必靠扫描签名定位图片。第二条 kind1300 在 `0x5312`，尺寸278×87。

已原样提取并实际查看这两幅PNG：第一幅是兔子插画，第二幅是绿色“函数的图象”标题图（可见作者张庆连）；它们是文档内的图片资产，未由此声称它们是软件截图或页面预览。

| 输出 | 原文件字节范围（左闭右开） | PNG SHA256 |
|---|---|---|
| PNG 128×128（原文件E内） | E `[426,21266)` | `d763a91461298a6e7558d21f8319e3e56c6f4ac044583ba0b9ec18d1c9185c45` |
| PNG 278×87（原文件E内） | E `[21282,30980)` | `cf2760e7f7544d5df341b09d016bae11c3845e06acb2be893bff3b9a09c0ffa9` |

kind1100在E中共有19条，均在不同1000区间内。首条记录在`0x7A1E`，payload在`0x7A26`，字节为`E9 A6 96 E9 A1 B5 00 FF`；首个NUL之前按UTF-8得到“首页”。后续页面候选为“描点法”“直线”“抛物线1”“抛物线2”“双曲线”“多图象”，以及带1440或1360后缀的同类名称。全库1,910条名称候选及原始payload保存到`gsp-name-candidates.json`。脚本只是按首NUL截断、依次尝试严格UTF-8/GBK解码；这种启发式结果不证明所有字符串编码，也不推断尾部字节的含义。

全库字节搜索还看到 73 个文件包含 `78 9C`、81 个包含 `78 DA`、327 个包含 `78 01`，以及11个文件包含 JPEG 起始候选 `FF D8 FF`。这些只是短字节模式命中，未据此声称存在相应压缩流或有效 JPEG；PNG 的压缩数据和普通数值也可能产生同样字节。

补齐实例：E 的 kind9009 在十进制83978，payload 长25；payload 起于83986、止于84011，随后有一个 `00`，下一记录为84012。不补齐会在后续误读记录类型或在 EOF 留下1字节。

## 静态格式证据的限制

目前足以实现覆盖现有全部样本的**只读记录遍历器**、层级容器检查器和kind1300图片提取器；这并不等于能重建或正确渲染图形。

仅靠本次字节扫描未确认：kind2000中各字段的名称和位标记、kind2002索引引用的编号基准与生命期、各对象子类映射、变换/表达式/迭代规则、页面与工具脚本的区别、1002/1003及902的精确语义、字符串长度与编码的完整约定、未知payload的压缩情况、完整写回规范以及CRC/其他完整性字段是否存在。

对象头和父引用的后续函数级证据见[对象头](../recovered/native/RECOVERY-object-header.md)与[父引用](../recovered/native/RECOVERY-parent-references.md)，包括kind2002保存编号和加载映射；不要将上面的静态扫描局限当作当前实现状态。完整读写验收与任务顺序见[总计划](../recovered/PLAN.md)。
