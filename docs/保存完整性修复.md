# 保存完整性修复与验收（2026-11-06）

## 2026-11-10 后续复核

发现此前模型比较把带 `fromFile` 标记的显示精度和文本样式当作默认值，完整重编码可能在不报警的情况下重置这些设置。现写入角度、距离、其他数值的精度以及已确认格式的文档文本样式，并比较实际设置；尚无法证明可保留的设置继续要求转存。原版画面进一步确认，已有度量和计算使用对象自身的精度：新版现读取度量记录中的精度，写出度量、计算和新建参数时保留对象值或文档默认值，比较器也只在确实等于相应默认值时将省略与显式精度视为相同。自制文件含 4、3、1 位精度、非斜体及两类自定义字体样式，经原版打开、另存后内容一致；回归还覆盖来源标记、标签斜体继承和不受支持的颜色、字体。此前版本的“审计中差异被放行 0”不覆盖被旧比较器忽略的字段，不能用来证明这类设置未丢失；更新后的全库审计见[兼容性报告](兼容性报告.md)。

本轮落实 `reference/spec/项目现状审查.md` 的 P0 保存保护与审计，并整理失实的状态口径、修复桌面文件启动入口。不是审查文档所有 P1/P2 功能完成声明。未启动原版、未修改原版样例、未操作用户鼠标或剪贴板。

## 保存行为

- 未修改的导入 `.gsp`：从读取时的内容快照判断，逐字节另存；改文件名、切页、滚动不触发重编码。内容改后再撤销至原状也可原样另存。
- 修改过的导入文件：自由点位置以及已知的颜色/隐藏/追踪/点型/线型字段，优先直接修改源记录中的定长字段，其余字节全部保留，并重读核对；其它修改先检验写入器是否能逐字节重建源课件。不能证明原格式信息完整保留时，拒绝重写 `.gsp`，提示另存当前模型为 `.ngsp`，原文件保留。这个限制比旧版本严格，防止未解码的设置、标签格式或记录在重建时消失。
- 新建文档或可证明可重建的来源：编码后重读，对比所有已建模内容；发现变化就停止写入，提示转存。取消转存不改变来源、不清除未保存标记。
- `.ngsp` 完整保留新版当前文档模型；它不是原版未知记录的归档容器，不承诺还原尚未读取的原版信息。需要原始信息时保留原 `.gsp`。
- 原子写入仍负责磁盘完整性；新增模型校验负责发现课件内容变化，两者不能互相替代。
