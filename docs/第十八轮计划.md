# 第十八轮计划：最低分课件的原因与改法

2026-11-14。以下保留原计划，实施结果、夹具更正和待核实项见 [兼容性报告](兼容性报告.md#第十八轮实施)。

## 结论先行

最低的十几份课件不是各有各的问题，而是六类共性原因。其中两类此前的结论是错的：

| 课件 | 之前的说法 | 实际原因 |
|---|---|---|
| 0912、0302、0954、0406 | 动画课件，静态不可比；0954 没有启动记录 | 求值和静态画面都对（去掉选中记录后原版与新版对照 0.97–1.00）。低分只因为原版截图时动画已在跑。0954 有 `9000` 记录 |
| 1122、1261、1262 | 数值混沌，不可复现 | 可以复现。新版单位长度经“像素→厘米→像素”差了 1 个最低有效位，5 万步后走到不同轨道 |
| 925 份课件（含 0901、0563） | — | `9000` 是保存时的选中对象，原版打开后画选中框，新版不画 |
| 0653、0901、0563 | 未查 | 函数图像取样数封顶、不画箭头；网格步长固定 1 单位；单位小于 2 像素时不画坐标系；三点比值名字错 |
| 1413 | 未查 | 黑体行距套用了 Times 的公式；上下标位置 |
| 0496 | 楷体→斜体 | 只有一个标签，字体待查 |

## 步骤

按“收益大、风险小”排在前面。每步先做原版夹具（规则已知的除外），再改代码，再整批对照改前改后。

### 1. 选中状态（`9000`）

预期：整库平均约 +0.014（约 900 份各 +0.02），24 份自动执行的课件 0.755 → 0.965。

1. 模型：`Page.startupButtons` 改名为 `savedSelection`，语义改成“保存时选中的对象”，不再过滤掉非按钮对象。
2. 打开文件：把这些对象设为选中；其中的动画、移动、系列按钮照旧执行。
3. 保存：写出当前选中对象（原版就是这样）。未修改另存仍须逐字节一致。
4. 对照口径：`render-library.ts` 默认画选中状态（`--saved-selection` 已加）。24 份会自动执行的课件，原版基准改用 `tools/strip-selection.ts` 去掉记录后的截图，新版相应不画选中；在报告里写明这 24 份的口径。
5. 夹具：隐藏/显示、链接、声音、演示、滚动按钮被选中时，原版打开是否执行；选中的点、线、文字、按钮各自的选中外观与新版是否一致。

### 2. 坐标系

1. 十进制坐标系的网格线步长改用已有的 `numericGridStep`（0901）。夹具：`patch_axis_unit.py` 取 6 个单位长度核对。
2. 去掉“单位小于 2 像素不画”的保护（0563），改成按循环次数设上限。
3. π 轴数字步长的边界（恰好 80 像素取不取，0653）。

### 3. 名字和公式

1. 三点比值的名字改成上下式 `AD/AC`（0653）。
2. 函数表达式里的 `f` 和 `x` 按“数学标签用斜体”画斜体（0901、0653、0563）。
3. 中文度量名的斜体（0563）：第十七轮只让拉丁字母斜体，先找出当时的依据课件，再用夹具分清是字体不同还是规则不同。
4. “点的值”度量的名字 `J在L₁上`（0912）。
5. 文字里上下标的位置和字号（1413）。

### 4. 函数图像

1. 夹具定 `2306` 偏移 22 的两位（推测是连续/离散、显示箭头和端点），解码并画出箭头和端点。
2. 取样：去掉 4000 的封顶，定出原版的取样位置。0653 是现成的检验（每周期不到一个样本，画面由取样位置决定）：候选规则逐个模拟，和原版截图比频谱主峰（237 周/1190 像素）和逐像素重合。
3. 性能：样本数很大的图像只算视口内的那一段。

### 5. 行距

按字体统计全库多行文字的“文本框高 ÷ 行数”，得到各字体的行距（不需要开原版），替换 `gdiLineHeight` 里“其余字体按 Times”的分支。宋体、黑体、楷体预计是 1 倍字号。

### 6. 迭代的精确算术（1122、1261、1262 及其他轨道分形）

收益最确定但改动最深，放在显示类改完之后。

1. 解码保留平移记录里的像素值，不再除以 `96/2.54` 存厘米再乘回；新建对象按 `厘米×96÷2.54` 的顺序换算。
2. 坐标轴对齐时，`toSys`、`fromSys` 用 `(p−原点)÷单位`、`原点+值×单位`，不走叉积除以行列式。
3. 迭代快路径（`iterfast.ts`）用同样的运算顺序，快慢路径逐位一致的测试保留。
4. 验收用逐像素对照，不用“看着像”：把 `tools/r18-hopalong-match.py` 的办法做成对新版引擎输出的检查，1122 与原版截图的交并比应达到独立模拟的 0.87。
5. 1261、1262 含 sin、ln、tan。改完第 1–3 步后同样逐像素比；仍分叉就用小夹具（逻辑斯蒂映射迭代 60–100 步，读迭代数据表）分清是函数实现的末位差异还是别的运算顺序。函数末位差异无法在浏览器里消除，那时才把这两份改成“点数和分布相近”的口径。
6. 影响：全库求值结果在 1e-16 量级变化，`drag-survey` 聚合指纹和 Mira 指纹要重定基线，保存审计的“模型一致”数字要重跑。

### 7. 收尾项

- 0496 的标签字体。
- 0576、1025、0579 第十七轮下降 0.01–0.03，逐份并排看。
- 动画本身的对照（参数速率、自由点方向）：第 1 步之后，原版“带选中记录”和“去掉记录”两张截图的差就是动画效果，可以据此逐项标定。0954 的参数 `n` 是慢速往返，两次截图分别是 3 和 4。

## 验收

1. `npm test`、浏览器 e2e、`npm run build`。
2. 整库重绘加打分：平均分、≥0.95 份数、下降的份数（应为 0 或逐份有解释）。第 1–5 步完成后平均分预计在 0.94 以上。
3. `npm run scan -- ../sketchpad5`、`npx tsx tools/roundtrip-audit.ts ../sketchpad5`：读取 1,431/1,431、未修改逐字节另存 1,431/1,431、差异被放行 0。
4. 目标课件逐份并排看图：0912、0302、0954、0406、0901、0653、0563、1413、0496、1122、1261、1262。
